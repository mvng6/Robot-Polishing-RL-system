## 📈 1. episode_reward_components.png

### 그래프 구성

**왼쪽 Y축 (Reward Components)**: 보상 계산 과정의 중간 값들
**오른쪽 Y축 (Control Performance Metrics)**: 실제 제어 성능 지표

### 보상 구성 요소 (Reward Components)

#### 1. `reward_score` (파란색)
**의미**: 원시 보상 스코어 (0~1 범위, 이론적)

**계산식**:
```python
reward_score = 
    0.30 * S_ts          # 정착시간 스코어
  + 0.35 * S_mp          # 오버슈트 스코어
  + 0.20 * S_ess         # 정상상태 오차 스코어
  + 0.15 * S_band        # 밴드 유지 스코어
  + 0.05 * S_u           # 제어 노력 스코어
  - 0.15 * P_fail        # 추종 실패 패널티
  - P_early              # 초기 구간 피크 패널티 (최대 0.2)
  + 0.10 * progress      # PBRS 개선 신호
  + 0.10 * I_improve     # 기준선 대비 개선
```

**해석 방법**:
- ✅ **높을수록 좋음** (1에 가까울수록)
- 실제 제어 성능을 종합적으로 평가한 **원시 점수**
- 이론적으로는 0~1 범위이지만, 패널티와 개선량에 따라 음수 가능
- **중요**: 이 값이 음수라도 실제 성능이 나쁜 것은 아님 (기준선 중심화 때문)

**예상 값**:
- 좋은 성능: 0.3 ~ 0.7
- 보통 성능: 0.0 ~ 0.3
- 나쁜 성능: -0.2 ~ 0.0

---

#### 2. `r_baseline` (빨간색, 점선)
**의미**: 보상 기준선 (EWMA, Exponential Weighted Moving Average)

**계산식**:
```python
# 처음 초기화
r_baseline = 0.5  # 초기값 (중립)

# 매 에피소드마다 업데이트
r_baseline = 0.99 * r_baseline + 0.01 * reward_score
```

**해석 방법**:
- ✅ **동적 기준선**: 최근 100 에피소드 정도의 가중 평균
- **중요**: 이 기준선이 점점 내려간다면 → 전반적 성능이 악화됨
- **중요**: 이 기준선이 점점 올라간다면 → 전반적 성능이 개선됨
- `reward_score`를 추적하는 **추종 신호** (β=0.99로 매우 느리게 추종)

**예상 값**:
- 초기: 0.5 (중립)
- 이후: `reward_score`의 평균 수준으로 수렴
- 만약 -0.1 ~ -0.2 사이에 있다면 → 전반적으로 낮은 성능

---

#### 3. `r_centered` (초록색)
**의미**: 기준선 중심화된 보상 (reward_score에서 기준선을 뺀 값)

**계산식**:
```python
r_centered = reward_score - r_baseline
```

**해석 방법**:
- ✅ **상대적 성능**: 기준선 대비 얼마나 좋은지/나쁜지
- **중요**: 이 값이 양수면 → 기준선보다 좋은 성능
- **중요**: 이 값이 음수면 → 기준선보다 나쁜 성능
- 에이전트가 실제로 최적화하는 보상 (SAC 알고리즘에 전달됨)

**예상 값**:
- 기준선보다 좋은 성능: 0.1 ~ 0.3
- 기준선 수준: -0.1 ~ 0.1
- 기준선보다 나쁜 성능: -0.3 ~ -0.1

**학습 해석**:
- `r_centered`가 지속적으로 음수면 → 에이전트가 기준선보다 못하고 있음
- `r_centered`가 지속적으로 양수면 → 에이전트가 기준선보다 잘하고 있음
- `r_centered`가 점점 올라간다면 → 학습이 잘 되고 있음

---

### 제어 성능 지표 (Control Performance Metrics)

#### 1. `overshoot %` (노란색/주황색)
**의미**: 목표값을 넘어선 최대 편차 비율

**계산식**:
```python
# 음수 목표 힘 (-40N)인 경우
extreme_force = min(force_array)  # -70N (예)
overshoot = (target_force - extreme_force) / abs(target_force) * 100
# = (-40 - (-70)) / 40 * 100 = 30/40 * 100 = 75%
```

**해석 방법**:
- ❌ **낮을수록 좋음** (0에 가까울수록)
- 목표 힘을 얼마나 초과했는지 나타냄
- **중요**: 이 값이 높으면 → 초기 오버슈트가 심함 → 보상 페널티 증가

**예상 값**:
- 좋은 성능: 0 ~ 30%
- 보통 성능: 30 ~ 60%
- 나쁜 성능: 60 ~ 100%+

**그래프 해석**:
- 평균 91.7% → 실제 힘이 평균 -76.7N까지 갔다는 의미
- 피크 100%+ → 실제 힘이 -80N 이상까지 갔다는 의미

---

#### 2. `settling_time` (보라색)
**의미**: 목표값에 도달하여 안정화되는 시간 (초)

**계산식**:
```python
# ±1.0N 범위 내에서 0.5초 연속 유지 시작 시간
settling_time = 첫 번째로 밴드 내 유지 시작 시간
```

**해석 방법**:
- ❌ **짧을수록 좋음** (0에 가까울수록)
- 빠르게 목표에 도달하고 안정화되는 것이 좋음

**예상 값**:
- 좋은 성능: 0.5 ~ 2.0초
- 보통 성능: 2.0 ~ 5.0초
- 나쁜 성능: 5.0초 이상

---

#### 3. `band_ratio %` (빨간색/갈색)
**의미**: 허용 오차 범위(±1.5N) 내에 머무는 시간 비율

**계산식**:
```python
band_ratio = mean(|error| <= 1.5N)  # 0~1
band_ratio % = band_ratio * 100  # 0~100%
```

**해석 방법**:
- ✅ **높을수록 좋음** (100에 가까울수록)
- 목표값 근처에 얼마나 오래 머무는지 나타냄

**예상 값**:
- 좋은 성능: 70 ~ 100%
- 보통 성능: 40 ~ 70%
- 나쁜 성능: 0 ~ 40%

## 📊 2. episode_reward_comparison.png

### 그래프 구성

**두 가지 보상 비교**:
1. `reward_score` (파란색): 원시 보상 스코어
2. `reward` (녹색): 최종 보상 (tanh 적용 후)

### 보상 변환 과정

```python
# Step 1: 원시 보상 스코어 계산 (0~1, 이론적)
reward_score = 0.30*S_ts + 0.35*S_mp + ... - P_fail - P_early + ...

# Step 2: 기준선 중심화
r_centered = reward_score - r_baseline

# Step 3: tanh 소프트클립 (최종 보상)
reward = tanh(2.0 * r_centered)
# → 범위: [-1.0, 1.0]
```

### 해석 방법

#### `reward_score` (파란색)
- **의미**: 원시 성능 점수
- **범위**: 이론적으로 0~1, 실제로는 음수 가능
- **특징**: 실제 제어 성능을 직접적으로 반영
- **해석**: 
  - 음수 → 전반적으로 낮은 성능
  - 0 근처 → 평균 수준
  - 양수 → 좋은 성능

#### `reward` (녹색, tanh 적용)
- **의미**: SAC 알고리즘에 전달되는 최종 보상
- **범위**: -1.0 ~ 1.0 (tanh 함수로 제한됨)
- **특징**: 기준선 중심화 + tanh 클리핑으로 안정적 학습 유도
- **해석**:
  - **중요**: 이 값이 양수면 → 학습이 잘 되고 있음
  - **중요**: 이 값이 점점 올라간다면 → 성능 개선 중
  - tanh 함수 특성상 기준선 근처에서는 작은 변화도 크게 보임

### 두 지표의 관계

**시나리오 1: `reward_score`는 음수, `reward`는 양수**
```
reward_score (MA10) = -0.05 (나쁜 성능)
r_baseline = -0.15 (기준선도 낮음)
r_centered = -0.05 - (-0.15) = +0.10 (기준선보다 좋음!)
reward = tanh(2.0 * 0.10) = tanh(0.20) ≈ 0.20 (양수)
```
→ **해석**: 절대 성능은 낮지만, 기준선보다는 좋아서 양수 보상

**시나리오 2: `reward_score`는 개선, `reward`는 정체**
```
초기:
  reward_score = -0.10
  r_baseline = -0.10
  r_centered = 0.0
  reward = tanh(0.0) = 0.0

나중:
  reward_score = -0.05 (개선!)
  r_baseline = -0.08 (기준선도 따라올라옴)
  r_centered = -0.05 - (-0.08) = +0.03 (약간 개선)
  reward = tanh(2.0 * 0.03) = tanh(0.06) ≈ 0.06 (약간 양수)
```
→ **해석**: 절대 성능은 개선되었지만, 기준선도 따라올라와서 상대적 개선은 작음

## 🔍 종합 해석 가이드

### 1. 학습이 잘 되고 있는지 확인

**✅ 좋은 신호:**
- `r_centered (MA10)`가 점점 올라감
- `reward (MA10)`가 양수 영역에서 점점 올라감
- `overshoot %`가 점점 감소
- `band_ratio %`가 점점 증가

**❌ 나쁜 신호:**
- `r_centered (MA10)`가 지속적으로 음수
- `reward_score (MA10)`가 계속 하락
- `overshoot %`가 계속 증가
- `settling_time`이 계속 증가

### 2. 현재 상태 진단

**상태 A: `reward_score`는 낮지만 `reward`는 양수**
```
→ 기준선 중심화가 작동 중
→ 절대 성능은 낮지만, 기준선 대비는 좋음
→ 학습은 진행 중이지만, 절대 성능 개선 필요
```

**상태 B: `reward_score`와 `reward` 모두 음수**
```
→ 절대 성능도 낮고, 기준선 대비로도 나쁨
→ 학습이 제대로 되지 않음
→ 보상 함수나 하이퍼파라미터 재검토 필요
```

**상태 C: `reward_score`와 `reward` 모두 양수**
```
→ 절대 성능도 좋고, 기준선 대비로도 좋음
→ 학습이 잘 되고 있음
→ 현재 설정 유지
```

### 3. 문제 해결 방향

**문제: `overshoot %`가 높음 (90%+)**
```
원인: 초기 압력 급격한 변화 (0 → 0.3MPa)
해결:
  1. 초기 접촉 압력을 0.1MPa로 올리기
  2. State space에 초기 구간 정보 추가
  3. 보상 함수의 오버슈트 가중치 강화
```

**문제: `reward_score`가 계속 하락**
```
원인: 제어 성능이 악화되고 있음
해결:
  1. PID 범위 재조정
  2. 탐색 전략 조정
  3. 보상 함수 재검토
```

**문제: `r_centered`가 음수로 정체**
```
원인: 기준선 대비 성능이 개선되지 않음
해결:
  1. 기준선 업데이트 속도 조정 (β 값)
  2. 학습률 조정
  3. 더 많은 에피소드 학습
```
