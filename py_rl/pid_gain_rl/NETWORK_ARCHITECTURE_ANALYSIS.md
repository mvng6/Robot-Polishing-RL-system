# 🔍 신경망 구조 확장 필요성: 비판적 분석

## 📊 현재 신경망 구조

### Phase 1 (현재)
- **Actor**: 128-128 2층 MLP (20차원 입력 → 3차원 출력)
- **Critic**: Dual Q-Network, 각각 128-128 2층 MLP (23차원 입력 → 1차원 출력)
- **상태 공간**: 20차원 (로봇PC 6차원 + 강화학습PC 6차원 + 궤적 요약 8차원)

### 문제 제기: Phase가 올라갈수록 신경망을 복잡하게 해야 하는가?

## 🤔 비판적 분석

### **1. LSTM이 정말 필요한가?**

#### ✅ LSTM이 필요할 수 있는 이유:
- **Phase 3+**: 목표 접촉력이 시간에 따라 변경됨
- **시계열 메모리**: 이전 목표 히스토리를 기억해야 함
- **시간적 의존성**: 목표 변경 패턴 학습 가능

#### ❌ LSTM이 불필요한 이유:

**1. 명시적 상태 정보 제공 가능**
```python
# 상태 공간에 목표 히스토리를 명시적으로 포함
state = [
    current_force,           # 현재 힘
    current_target,          # 현재 목표 힘 (명시적!)
    previous_target,         # 이전 목표 힘
    next_target,            # 다음 목표 힘 (예측 가능)
    target_change_time,      # 목표 변경 시점
    time_since_change,      # 변경 후 경과 시간
    ... (기존 20차원)
]
# 총 24-26차원 → LSTM 없이도 충분!
```

**2. 목표 변경은 명시적으로 알려줄 수 있음**
- 로봇제어PC에서 목표 변경 시 신호 전송 가능
- 환경에서 목표 히스토리를 직접 제공 가능
- **LSTM의 암묵적 메모리보다 명시적 정보가 더 안정적**

**3. LSTM의 단점**
- 학습 난이도 증가 (gradient vanishing/exploding)
- 하이퍼파라미터 튜닝 복잡도 증가
- 학습 시간 증가
- 현재 MLP 구조로 이미 잘 작동 중

**4. 현재 문제의 성격**
- **PID 제어**: 현재 상태와 목표 힘의 관계가 핵심
- **단기 메모리**: 목표 히스토리는 최근 2-3개만 필요 (LSTM 과함)
- **마르코프 성질**: 현재 상태만으로도 충분히 결정 가능

---

### **2. 신경망을 점점 복잡하게 해야 하는가?**

#### ✅ 복잡하게 만들어야 하는 경우:

**Phase 1 → Phase 2-3: 상태 공간 확장**
- 목표 히스토리 정보 추가 (4-6차원)
- 시간 인코딩 추가 (2차원)
- **총 24-26차원** (20차원 → 24-26차원)

**Phase 3+: 숨겨진 층 추가 또는 크기 증가?**
- 현재: 128-128 2층
- 확장: 256-256-128 3층? 또는 256-256 2층?

#### ❌ 복잡하게 만들지 않아도 되는 이유:

**1. 상태 공간 확장만으로 충분할 수 있음**
```python
# 현재: 20차원 → MLP 128-128 (충분한 표현력)
# 확장: 24-26차원 → MLP 128-128 (여전히 충분할 가능성)
```

**2. 과적합 위험**
- 더 복잡한 네트워크 = 더 많은 데이터 필요
- 로봇 실험은 비용이 큼 (에피소드당 실제 시간 소요)
- 현재 1000-1250 에피소드로는 과적합 가능성

**3. 전이학습 관점**
- Phase 1에서 학습한 가중치를 Phase 2+에서 재사용
- 네트워크 구조가 바뀌면 전이학습 불가능!
- **구조 일관성이 전이학습에 필수**

**4. "더 복잡 = 더 좋음"은 착각**
- 작은 문제는 간단한 모델이 더 좋을 수 있음
- 현재 PID 게인 최적화는 비교적 단순한 문제
- 128-128 MLP로 충분한 표현력 확보 가능

## 🎯 권장 접근법: 점진적 상태 공간 확장

### Phase별 신경망 구조 제안

#### **Phase 1 (현재)**
```
상태: 20차원
Actor: 128-128 MLP (20 → 128 → 128 → 3)
Critic: 128-128 MLP (23 → 128 → 128 → 1) × 2
```

#### **Phase 2: 상태 공간만 확장**
```
상태: 22차원 (기존 20 + 목표 범위 정보 2)
  - current_target_normalized: 현재 목표 힘 정규화
  - target_range_span: 목표 범위 폭 (-35 ~ -50 = 15N)
Actor: 128-128 MLP (22 → 128 → 128 → 3) ← 입력 차원만 변경
Critic: 128-128 MLP (25 → 128 → 128 → 1) × 2
구조 변경 없음, 전이학습 가능!
```

#### **Phase 3: 목표 히스토리 추가**
```
상태: 26차원 (기존 20 + 목표 정보 6)
  - current_target_normalized
  - previous_target_normalized
  - time_since_episode_start (에피소드 내 시간)
  - time_to_next_change (다음 변경까지 시간)
  - target_change_count (현재까지 변경 횟수)
  - episode_phase (0=시작, 1=중간, 2=끝)
Actor: 128-128 MLP (26 → 128 → 128 → 3) ← 입력 차원만 변경
Critic: 128-128 MLP (29 → 128 → 128 → 1) × 2
구조 변경 없음, 전이학습 가능!
```

#### **Phase 4: 최종 확장 (선택적)**
```
상태: 28차원 (Phase 3 + 2차원)
  - target_velocity (목표 변경 속도 추정)
  - prediction_error (예측 오차)
Actor: 128-128 MLP (28 → 128 → 128 → 3)
Critic: 128-128 MLP (31 → 128 → 128 → 1) × 2
구조 변경 없음!
```

## ⚠️ LSTM 도입 시 고려사항

### LSTM이 정말 필요한 경우 (나중에 검토)

**조건 1**: 명시적 상태 정보로 해결 불가능
- 목표 변경 패턴이 복잡하고 예측 불가능
- 장기 의존성 필요 (10초 이상)

**조건 2**: Phase 4에서도 성능 부족
- 상태 공간 확장 후에도 성능 미달
- 명시적 정보만으로는 부족함을 실험적으로 확인

**조건 3**: 학습 데이터 충분
- 최소 2000+ 에피소드 학습 가능
- LSTM 학습에 필요한 충분한 데이터

### LSTM 도입 시 구조 (참고만)

```python
class ActorLSTM(nn.Module):
    def __init__(self, state_dim, action_dim, hidden_dim=128, lstm_dim=64):
        super().__init__()
        self.lstm = nn.LSTM(state_dim, lstm_dim, batch_first=True)
        self.fc1 = nn.Linear(lstm_dim, hidden_dim)
        self.fc2 = nn.Linear(hidden_dim, hidden_dim)
        self.mean_head = nn.Linear(hidden_dim, action_dim)
        self.log_std_head = nn.Linear(hidden_dim, action_dim)
    
    def forward(self, state_seq):  # state_seq: [batch, seq_len, state_dim]
        lstm_out, _ = self.lstm(state_seq)
        x = lstm_out[:, -1, :]  # 마지막 시퀀스만 사용
        x = F.relu(self.fc1(x))
        x = F.relu(self.fc2(x))
        mean = torch.clamp(self.mean_head(x), -10.0, 10.0)
        log_std = torch.clamp(self.log_std_head(x), -3.0, -1.0)
        return mean, log_std
```

**문제점**:
- Replay Buffer 구조 변경 필요 (시퀀스 저장)
- 학습 시간 증가 (LSTM 순전파/역전파)
- 하이퍼파라미터 튜닝 복잡도 증가 (lstm_dim, seq_len)
- 전이학습 시 구조 변경으로 인한 호환성 문제

## 💡 결론 및 권장사항

### ✅ 권장 접근법 (점진적 확장)

**1단계: 상태 공간만 확장 (Phase 1-4)**
- 입력 차원만 증가 (20 → 22 → 26 → 28)
- 네트워크 구조는 **128-128 유지**
- 전이학습 가능, 구조 일관성 유지

**2단계: 필요 시 네트워크 크기 증가 (Phase 4+)**
- 128-128 → 256-256 (2배)
- 상태 공간 확장으로 부족할 때만

**3단계: LSTM 도입 (최후의 수단)**
- 위 모든 방법 실패 시에만
- 별도 실험으로 검증

### ❌ 권장하지 않는 접근법

1. **바로 LSTM 도입**: 복잡도 증가, 전이학습 어려움
2. **Phase마다 구조 변경**: 전이학습 불가능
3. **과도한 복잡화**: 로봇 실험 비용 고려 필요
