# 📊 200 에피소드 강화학습 결과 분석

## 🎯 요약

**결론: 현재 학습은 효과적으로 진행되지 않고 있습니다.**

### 핵심 문제점
1. **오버슈트가 모든 에피소드에서 90% 이상 유지** (매우 심각)
2. **보상이 개선되지 않음**: `reward_score (MA10)`가 0 근처에서 정체
3. **제어 성능 지표 전반적으로 악화 또는 정체**
4. **초기 접촉 압력 급격한 변화 (0 → 0.3MPa)가 주요 원인**

---

## 📈 상세 분석

### 1. 보상 구성 요소 분석

#### 1.1. Reward Score (원시 성능)
- **초기 (0-25ep)**: 0.15 → -0.15로 급격히 하락
- **중기 (25-125ep)**: -0.1 ~ -0.05 사이에서 변동
- **후기 (125-200ep)**: -0.05 ~ 0.0 사이에서 정체
- **결론**: 원시 성능이 전혀 개선되지 않음

#### 1.2. R_Centered (중심화된 보상)
- **초기 (0-25ep)**: -0.3 → -0.55로 급격히 하락
- **중기 (25-125ep)**: -0.5 ~ -0.4 사이에서 변동
- **후기 (125-200ep)**: -0.45 ~ -0.3 사이에서 개선 없음
- **결론**: 에이전트가 실제로 최적화하는 보상이 개선되지 않음

#### 1.3. R_Baseline (기준선)
- `reward_score`를 잘 추적하며 -0.15 ~ -0.1 사이 유지
- 기준선 중심화가 제대로 작동하고 있지만, 실제 성능 개선이 없어 보상이 낮게 유지됨

#### 1.4. Final Reward (tanh clipped)
- `reward (MA10)`는 0.0 이상을 유지하며 긍정적으로 보임
- 하지만 이는 tanh 클리핑 효과로, 실제 성능 개선이 아닐 수 있음

---

### 2. 제어 성능 지표 분석

#### 2.1. 오버슈트 (Overshoot) ⚠️ **매우 심각**
- **초기 (0-25ep)**: 20% → 90% 이상으로 급격히 상승
- **전체 (25-200ep)**: 90% 이상을 유지하며 **전혀 개선되지 않음**
- **원인**: 초기 접촉 압력 0 → 0.3MPa 급격한 변화
- **결론**: 에이전트가 오버슈트를 제어하는 PID 게인을 전혀 학습하지 못함

#### 2.2. 정착 시간 (Settling Time)
- **전체**: 0.7초 이상을 유지하며 개선 없음
- 오버슈트가 심해 정착 시간이 길어짐

#### 2.3. 밴드 유지 비율 (Band Ratio)
- **초기 (0-25ep)**: 70% → 20% 미만으로 급격히 하락
- **전체 (25-200ep)**: 20-30% 사이에서 매우 낮은 수준 유지
- 목표 밴드 내 유지 시간이 매우 짧음

#### 2.4. 기타 지표
- **RMSE**: 4.5-10.5 사이에서 높은 변동성, 개선 없음
- **Steady State Error**: 0-7 사이에서 높은 변동성
- **Rise Time**: 0.05-0.30 사이에서 극심한 변동성
- **IAE**: 20-100 사이에서 높은 변동성

---

### 3. 학습 진행 여부 판단

#### ❌ 학습이 되지 않는 증거
1. **보상 정체**: `reward_score (MA10)`가 0 근처에서 개선 없음
2. **제어 성능 악화**: 오버슈트가 90% 이상으로 유지
3. **높은 변동성**: 모든 지표에서 변동성이 줄어들지 않음
4. **100ep 이후 정체**: 추가 개선 없음

#### 🔍 원인 분석
1. **환경 난이도**: 초기 접촉 압력 0 → 0.3MPa 급격한 변화가 PID 제어의 한계를 넘어섬
2. **보상 함수**: 오버슈트 페널티가 있지만, 에이전트가 이를 피할 수 있는 PID 게인을 찾지 못함
3. **탐색 범위**: 현재 PID 범위 내에서 최적해가 없을 수 있음
4. **초기 피크 패널티**: `early_peak_penalty`가 있지만 충분하지 않을 수 있음

## 💡 해결 방안

### 1. ✅ 즉시 적용: 초기 접촉 압력 변경 (사용자 제안)
**초기 접촉 압력을 0.1MPa로 올리기**

**기대 효과:**
- 초기 과도 응답 강도 감소
- 오버슈트 감소 가능성 높음
- 에이전트가 더 쉽게 학습 가능한 환경 제공

**구현 방법:**
- 로봇 제어 PC 측에서 초기 접촉 압력을 0.1MPa로 설정
- 에피소드 시작 시 즉시 0.1MPa로 설정된 상태에서 시작

---

### 2. 보상 함수 추가 강화

#### 2.1. 초기 구간 피크 패널티 강화
현재 설정:
```python
EARLY_PEAK_TIME_WINDOW = 0.5  # 0~0.5초 구간
EARLY_PEAK_PENALTY_SCALE = 0.2
EARLY_PEAK_PENALTY_MAX = 0.2
```

**제안:**
```python
EARLY_PEAK_TIME_WINDOW = 1.0  # 0~1.0초 구간으로 확장
EARLY_PEAK_PENALTY_SCALE = 0.4  # 0.2 → 0.4 (2배 강화)
EARLY_PEAK_PENALTY_MAX = 0.3  # 0.2 → 0.3 (상한 확대)
```

#### 2.2. 오버슈트 가중치 추가 강화
현재 설정:
```python
SCORE_W_MP = 0.35  # 오버슈트 가중치
SCORE_TAU_MP_PERCENT = 8.0  # 오버슈트 민감도
```

**제안:**
```python
SCORE_W_MP = 0.45  # 0.35 → 0.45 (더 강화)
SCORE_TAU_MP_PERCENT = 5.0  # 8.0 → 5.0 (더 민감하게)
```

---

### 3. PID 범위 재검토

현재 범위:
```python
Kp: [3.0, 40.0]
Ki: [0.0, 40.0]
Kd: [1e-4, 5e-2]
```

**문제점:**
- Kd 범위가 너무 넓어 탐색이 비효율적일 수 있음
- 오버슈트 억제를 위한 최적 Kd 값이 범위 밖에 있을 수 있음

**제안 (초기 압력 변경 후 시도):**
```python
# 오버슈트 억제에 집중
Kp: [3.0, 30.0]  # 상한 축소 (더 보수적)
Ki: [0.0, 30.0]  # 상한 축소
Kd: [1e-3, 1e-2]  # 범위 축소 (더 집중적 탐색)
```

---

### 4. 컨트롤러 측 사전 조치 (Controller-side Pre-actions)

**우선순위 높음:**
1. **Anti-windup**: 적분 게인 과다 적분 방지
2. **D-on-measurement with LPF**: 미분 게인 노이즈 필터링
3. **Input rate limit**: 제어 입력 변화율 제한
4. **Bumpless transfer**: PID 게인 변경 시 부드러운 전환

이러한 사전 조치들이 오버슈트를 크게 줄일 수 있습니다.

---

현재 설정:

```python
ACTOR_LOG_STD_MAX = -0.3  # 탐색 범위
ACTOR_INITIAL_ALPHA = 0.1

```

**제안 (초기 압력 변경 후 시도):**

```python
# 더 집중적인 탐색
ACTOR_LOG_STD_MAX = -0.5  # -0.3 → -0.5 (탐색 범위 축소)
```
